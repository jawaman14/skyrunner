# Code review and plan, October 2026

A whole-repo pass after the radio, Mount & Blade, tutorial, effects, voice-chat and waiting-room work. It
looks for what to finish, what to combine, what to remove and what needs work, then ranks it. Numbers come
from a static scan (`scripts/` and `tests/`), so "unreferenced" means "no other script or test names it",
which misses calls made by string (`call("_cmd_" + name)`), and is flagged as such below.

## The size of it

| Area | Lines | Note |
|---|---|---|
| `scripts/sim` | 21,600 | the simulation; half of the project |
| `scripts/ui` | 4,900 | menus, widgets, lobby, multiplayer, room |
| `scripts/render` | 4,800 | meshes, city, FX, lighting |
| `scripts/game` | 3,900 | the 3D pilot app, walker, car, radio, sound |
| `scripts/station` | 2,000 | the 2D desks |
| `scripts/util`, `balance`, `net`, `bots` | 1,870 / 1,760 / 1,750 / 1,470 | |
| **Total** | **44,400 in 152 files** | plus 14,100 lines in 86 test files (about 700 tests) |

Repository weight: `.git` 145 MB, `assets/models` 95 MB, `docs` 68 MB (27 MB screenshots, 41 MB video),
`assets/ui` 21 MB, `assets/radio` 12 MB, `reference/python` 4.4 MB.

The scan found **no TODO/FIXME markers, no identical duplicated function bodies, and no class that nothing
references.** The code is in better shape than its size suggests. The work is mostly in a few very large
files, in features that are built but not yet reachable or verified by a person, and in documents that have
fallen behind the code.

## 1. Finish (built, not done)

Ranked by how much a player would notice.

1. **Saves still drop whole systems.** `StrategicSave` keeps the stash houses, payroll, case, court, squads,
   renown, rackets, races and stash works, but not the Family, the island, trade (corner stock, market), the
   economy's prices, the HQ season, the two rival sides' squads, prisoners, or Logistics rounds. A reload in
   open mode therefore quietly resets them. Decide which are worth keeping (the Family, trade and prisoners
   are the visible ones) and add them to `strategic_save.gd` with a round-trip test each.
2. **Multiplayer has been verified on one machine only.** The waiting room (PR 45), the voice chat (real
   microphone, speakers, push-to-talk key, and the 8 kHz codec heard by a person), LAN discovery over a real
   network, and a guest seating from the room into `RemoteSeat` all pass tests with sockets on loopback and
   a dummy audio driver. Nobody has played them on two computers. Needs one real session and a fixes pass.
3. **Human-driven roles that DESIGN lists as "phase 3+".** The tables in `docs/DESIGN.md` still say
   boat captain, fixer, mechanic, analyst, undercover agent, cutter and interceptor are not playable. Some
   of that has since shipped (the interceptor has `RemoteSeat`); the rest is genuinely open. Audit, then
   either build the cheap ones (fixer and mechanic are mostly menus over systems that exist) or say "AI
   only, by design".
4. **Campaign chapters 5 to 8 are scripted in DESIGN but not playable.** The Costa Brava *story* (`Story.CHAPTERS`,
   eight chapters 1979 to 1986) is complete. The separate *campaign* (Palmetto Cay flying lessons) has four
   playable chapters; its 1983 to 1986 chapters (The Balloon, Blue Water, The Leak, Last Run / Flip) end with
   "arrive in the next phase", although the mechanics they teach (aerostat radar, encrypted radio, informants,
   decoys) exist in the HQ season. Build them or cut the campaign to four.
5. **Arena leftovers** (ROADMAP): a lap counter on the HUD, betting, races between players.
6. **Unverified by eye:** the club interior layout, the air-circuit race gates, and the room screen's look
   at 1080p and on a small window.
7. **Strategic balance drift.** ROADMAP item 1 left the equilibrium at 58.4% against a 50 ± 5% target, with
   the note "not tuned yet". Every feature since (veterans, rackets, renown, fuel, rounds) has shifted it
   again. Re-measure with the full 200-seed run, then tune once.
8. **BETA.md's balance note** was stale (it said a re-run was under way): fixed in the housekeeping PR.

## 2. Combine (the same thing done twice)

1. **Three seat/room screens that overlap.** `SeatPicker` (130 lines, in-game join), `RoomScreen` (the
   waiting room) and the Seats tab of `MultiplayerMenu` each list seats, who holds them and what they do.
   The seat descriptions are duplicated (`SeatPicker.ABOUT` and `Room.ABOUT`). Make `RoomScreen` the single
   seat view and have `SeatPicker` become a mode of it (a late joiner into a running game is the room with
   the game already started). One description table, in `Roles`.
2. **`LocalLink` and `NetClient` share an interface by convention only.** `StationApp`, `RemoteSeat`,
   `HostDesk` and `VoiceChat` take either. Write the interface down once (a small base class with the
   signals and `send`/`poll`), and let a test check that both implement all of it.
3. **`GameMenu` subclasses** (eight menus) each rebuild a title, close button and list in their own `_ready`.
   Lift the common frame, and move `Lobby._ready` (131 lines) and `MultiplayerMenu` (505 lines) onto it.
4. **`main.gd` start-up paths.** `start()`, `_join()`, `_seat()`, `_open_room()`, `_host_extras()`, `_enter_game()`
   all assemble "a server plus a voice node plus an announcer" in slightly different orders. One
   `_host_services(server)` helper, called from every path, removes the chance of one path forgetting the
   announcer or the voice node.
5. **Balance tooling.** `tactical`, `strategic`, `crew_sim`, `air_risk` (in `scripts/balance`) and
   `tools/live_balance.gd`, `equilibrium.gd` measure related things with separate argument parsing and
   separate result files. A single `cli.gd` front end with named configs would cut the entry points and
   stop `live_balance` configs growing as one-offs. `BalanceReport.write_report` is 311 lines and wants
   splitting by section.
6. **Static switches.** 17 `ENABLED` switches plus `REALISM` (4 files), `ENGAGEMENT`, `SMART_ROUTES`,
   `VETERANS`, `ROUNDS`, `PYTHON`. They exist for the parity tests and are tested. Keep them, but give them
   one registry (`Switches.parity_off()` and `restore()`) so a test doesn't have to know all of them, and
   so a new system can't forget to join. Today each test file toggles its own list.
7. **Scratch and demo scripts in `tools/`:** `tour`, `city_tour`, `ground_tour`, `ui_tour`, `demo`,
   `sound_demo`, `city_probe`, `screenshots.sh`, `record_demo.sh` overlap. Fold into one `tools/tour.gd
   --scene X`.

## 3. Remove (or stop shipping)

1. **Unreferenced functions: done in the housekeeping PR.** Twelve were removed (the old `Models.build_*`
   terrain, water and tree builders, the unused lat/lon helpers, `Py.dist3`/`dict_get`, `Airfield.is_short`,
   `Police.nearest_threat`, `StationApp.payroll_lines`, `City._buildings`, `Sound.stats`). The scan's other
   candidates were false positives and stay: the `Talk.State` methods (`money_s`, `cand_line`, `take_on`...)
   are called from the `.dialogue` scripts, `BigNat.divmod` and `PyRandom.get_state` are library API, and the
   `_cmd_*`, `_r_*` and `_p_*` functions are dispatched by name.
2. **`scripts/game/talk.gd` is live** (the phone, the talk balloons, the dialogue scripts and `test_talk.gd`).
3. **Unused 2D UI packs.** `assets/ui` (21 MB: cursors, emotes, explosions, flags, game icons, input
   prompts, map pack, minimap, road textures, ui pack) is referenced only by `test_assets.gd`, the export
   filter and LIBRARIES.md. No script loads it. Either use it (flags for factions, input prompts for the
   key hints, and cursors are the obvious three) or delete the rest from the tree, keeping the licences.
4. **Unused 3D packs, kept out of the export:** Kenney `pirate`, `survival`, `factory`, `retro_urban`,
   `modular_buildings`, `city_roads`; Quaternius `downtown_city` (23 MB), `stylized_nature` (19 MB). About
   60 MB in the working tree. Use them (docks from `pirate`, downtown from `downtown_city`) or remove them
   and re-add when needed. If any stay, record which scene will use each.
5. **`reference/python`** (4.4 MB, archival) and its frozen fixtures: keep the fixtures, move the prototype
   to a tag and delete the folder from `main`.
6. **Docs weight.** 41 MB of video and 27 MB of screenshots in `docs/`. Keep a handful of stills in the
   README, move video to a GitHub release, and stop committing regenerated screenshots (`.git` is 145 MB
   because of them).
7. **The stray `skyrunner-godot/` folder** in the repo root (untracked). Delete it, or ignore it in
   `.gitignore`; it keeps being one wrong `git add -A` away from a commit.
8. **Stale text:** the 19 `[phase 3+]` markers in DESIGN, and the `PYTHON` switch in `tactical.gd` if the
   Python comparison is no longer run.

## 4. Needs work (quality and structure)

1. **`scripts/sim/session.gd`, 2,955 lines and 175 functions, 88 of them `_cmd_*` handlers.** The command
   table is the natural seam: move command handlers into per-domain files (`cmds_air.gd`, `cmds_crew.gd`,
   `cmds_ground.gd`, `cmds_trade.gd`) registered into a dictionary, leaving Session with state, the tick and
   the save. Do it as pure moves with the golden and parity fixtures unchanged, which proves nothing changed.
2. **Other very large files:** `ground.gd` 1,586, `pilot_app.gd` 1,428 (with a 176-line `_unhandled_input`),
   `hq.gd` 1,305 (`finish_night` 142 lines), `station_app.gd` 1,202, `logistics.gd` 1,017, `police.gd` 962
   (`tick` 163 lines). Split by concern only where a change is already planned there; do not split for its own sake.
3. **Long functions** above 120 lines: `report.write_report`, `squads.sync` (178), `pilot_app._unhandled_input`,
   `police.tick`, `hq.finish_night`, `lobby._ready`, `chronicle.fire`, `station_app.setup`. Replace the key
   chains with an action map, and the render syncs with per-kind helpers.
4. **Tests missing for real code.** No test mentions: `FlightDynamics` (685 lines; covered indirectly by the
   flight golden), `LogisticsMenu` (320), `NightDirector` (289), `Vegetation` (210), `Lobby` (201), `HQOrders`
   (184), `HQBoard` (172), `AISmuggler` (164), `HangarMenu` (154), `Autopilot` (119), `Minimap` (119) and
   the menus for rackets, races and taxis. Start with `NightDirector`, `AISmuggler`, `Autopilot` and the
   three new menus: each is a cheap smoke test that builds the node and drives one action.
5. **Test run time.** 7 to 9 minutes headless for 700 tests, and two runs per push in CI. Group the suites
   that build a full `Session` and share one per file where the test only reads it, and mark the socket and
   rendering tests as a separate job so a logic-only change gets feedback in a couple of minutes.
6. **Determinism is documented in one table and enforced by hand.** Add a test that scans the sim for
   `randf`, `randi`, `RandomNumberGenerator.new()` without a seed, and `Time.get_ticks_*` outside an
   allow-list, so a new draw on a shared stream fails in CI rather than shifting a fixture.
7. **Repo hygiene in CI:** fail the build when a file under `tools/` is named `zz_*`, when `skyrunner-godot/`
   is tracked, or when an exported build includes anything under `tests/` or `assets/ui/`.
8. **Voice and network hardening.** The relay already caps frame size, rate and transmission length. Still
   open: the host cannot silence a disruptive player for everyone (mute is a listener-side setting only; kick
   is the only host power), and there is no test for a client that sends `voice` while the game is still in
   the room phase. Add both.
9. **Documentation drift.** `docs/MULTIPLAYER.md` is 128 lines and predates the room, voice and menu
   (DESIGN 31 to 33 hold that now); fold it in or rewrite it as the player-facing guide. ROADMAP's section 2
   reads as a changelog; move finished items into BALANCE/CHANGELOG and keep only open work.
